# Основы

## Выражения адресов

Везде, где нужен адрес (в окне, в CLI, в аргументах инструментов), можно писать:

| Форма | Пример | Значение |
|---|---|---|
| Число | `7f12a0`, `0x7f12a0` | По умолчанию числа **шестнадцатеричные** |
| Десятичное | `#4096` | `#` обозначает десятичное число |
| Модуль + смещение | `Game.exe+1A2B30`, `libgame.so+0x40` | Базовый адрес загруженного модуля плюс смещение |
| Имя в кавычках | `"My Game.exe"+10` | Для имён модулей с пробелами или дефисами |
| Разыменование | `[Game.exe+10]` | Прочитать указатель по этому адресу |
| Цепочка указателей | `[[Game.exe+1A2B30]+18]+40` | Пройти по указателям; переживает перезапуск |
| Арифметика | `0x7f12a0-0x40` | `+` и `-`, со скобками |

Адреса в куче меняются при каждом запуске игры. Цепочки указателей из **Pointer scan**
остаются прежними, поэтому сохраняй в таблицу их.

## Типы данных

| Тип | Размер | Примечание |
|---|---|---|
| `i8` `i16` `i32` `i64` | 1–8 | Целые со знаком. Для счётчиков чаще всего `i32` |
| `u8` `u16` `u32` `u64` | 1–8 | Целые без знака |
| `f32` `f64` | 4 / 8 | Дробные: здоровье, координаты, таймеры |
| `ptr` | 4 или 8 | Указатель; 4 байта в 32-битных играх |
| `bytes:N` | N | Сырые байты, записываются как `90 90 90` |
| `str:N` | N | Текст UTF-8 / ASCII |
| `str16:N` | 2N | Текст UTF-16 (часто в Unity/.NET и Windows-играх) |

Понимаются и синонимы: `int`, `dword`, `float`, `double`, `byte` и другие.

## Сканирование

Первый скан проходит по всей записываемой памяти (или по одному модулю с `module=`).
Следующий скан фильтрует текущих кандидатов.

| Сравнение | Первый скан | Следующий | Нужно значение |
|---|---|---|---|
| `exact` | ✓ | ✓ | да |
| `unknown` | ✓ | | нет |
| `greater` / `less` | ✓ | ✓ | да |
| `between` | ✓ | ✓ | два значения |
| `not_equal` | ✓ | ✓ | да |
| `changed` / `unchanged` | | ✓ | нет |
| `increased` / `decreased` | | ✓ | нет |
| `increased_by` / `decreased_by` | | ✓ | да |

- Тип **auto** ищет i32, i64, f32 и f64 одновременно. Кандидаты сортируются: выше типичные
  для счётчиков типы, память самой игры и правдоподобные дробные значения.
- **Дробные** числа сравниваются с округлением до введённых знаков: `100` совпадает с
  99,5…100,5, а `100.25` — с 100,245…100,255.
- **Байтовые шаблоны** понимают маску `??`: `48 8B ?? 05`. **Текст** ищется типами `string`
  и `string16`.
- Если число в игре масштабировано (проценты, ×10) или округлено, начни с `unknown` и сужай
  через `increased` / `decreased`.

## Цепочки указателей

Обычно значение лежит в объекте в куче. На этот объект ссылается статическая переменная в
модуле игры, иногда через несколько промежуточных объектов. **Pointer scan** ищет такие
цепочки от твоего адреса назад, глубиной до 5 и со смещениями до `max_offset`. Он оставляет
только цепочки, которые прямо сейчас приводят к адресу (✓ — проверено).

Чтобы запись не терялась, скопируй проверенную цепочку в поле Address, перезапусти игру и
убедись, что значение верное. Оставь цепочку, которая это пережила.

## Аппаратные точки останова

**Find writes / Find accesses** (`watch`) на несколько секунд ставит отладочный регистр
процессора во всех потоках цели. Для каждой инструкции, которая записала или прочитала адрес,
выводятся число срабатываний и регистры при первом срабатывании. Операнд памяти (`[rcx+18]`)
показывает, в каком регистре объект, а сама инструкция — то место, которое можно патчить.

## Заморозка

Замороженная запись периодически перезаписывается (`freeze_interval_ms`, по умолчанию 100 мс).
Заморозки действуют только в текущей сессии: снимаются при отключении или выходе из игры и не
сохраняются в таблице.
